## OBJETIVO PRINCIPAL
Gerar um sistema editável e legalmente seguro que replique:
- Arquitetura e estrutura de navegação
- Design system e identidade visual
- Padrões de UX/UI e componentes
- Responsividade e performance
- Funcionalidades e interações
**IMPORTANTE**: Substitua todo conteúdo protegido por placeholders, versões reescritas ou descrições técnicas. O foco é replicar o SISTEMA, não o conteúdo proprietário.
## METODOLOGIA DE ANÁLISE
### 1. MAPEAMENTO ESTRUTURAL COMPLETO
- Escaneie até \{MAX_DEPTH\} páginas do site
- Gere sitemap detalhado: URLs, hierarquias, tipos de página, meta-dados
- Identifique arquitetura da informação, fluxos de navegação e jornadas do usuário
- Mapeie taxonomias, categorias e relacionamentos entre páginas
### 2. ENGENHARIA REVERSA DO DESIGN SYSTEM
- **Tokens de Design**: Extraia paleta de cores (hex + função semântica), tipografia completa (fontes, pesos, escalas, espaçamentos), grid system e breakpoints
- **Componentes**: Documente todos os elementos reutilizáveis com suas variantes, estados e comportamentos
- **Padrões Visuais**: Sombras, bordas, ícones, animações, microinterações e transições
- **Layout**: Estruturas de grid, containers, espaçamentos e padrões responsivos
### 3. ANÁLISE TÉCNICA PROFUNDA
- **Performance**: Scripts, assets, otimizações, lazy-loading, critical CSS
- **SEO**: Estrutura de headings, schema markup, meta-tags, URLs amigáveis
- **Acessibilidade**: Contraste, navegação por teclado, ARIA labels, semântica
- **Tecnologias**: Stack detectado, frameworks, bibliotecas e padrões arquiteturais
### 4. BIBLIOTECA DE COMPONENTES
Para cada componente identificado, documente:
- Nome e categoria
- Propósito e contexto de uso
- Estrutura HTML/JSX
- Estilos e variantes
- Props/parâmetros configuráveis
- Comportamento responsivo
- Estados (hover, focus, active, disabled)
- Dependências e integrações
### 5. EXTRAÇÃO DE ASSETS
- Identifique assets públicos e reutilizáveis (ícones SVG, padrões gráficos)
- Para assets protegidos, crie placeholders com especificações técnicas
- Gere instruções para recriação de elementos visuais complexos
- Documente requisitos de assets (formatos, dimensões, otimizações)

## ESPECIFICAÇÕES DE CÓDIGO
**Para HTML/CSS/JS:**
- HTML5 semântico com estrutura modular
- CSS organizado (metodologia BEM ou CSS Modules)
- JavaScript vanilla otimizado
- Media queries bem estruturadas
- Comentários detalhados em áreas editáveis
**Para React + Tailwind:**
- Componentes funcionais com TypeScript (se aplicável)
- Props tipadas e bem documentadas
- Hooks customizados quando necessário
- Estrutura de pastas escalável
- Tailwind com configuração personalizada
- Storybook ou documentação de componentes
## DIRETRIZES LEGAIS E ÉTICAS
1. **Conteúdo Textual**: Limite cópias a trechos ≤ 25 palavras. Reescreva ou use placeholders para textos extensos
2. **Assets Protegidos**: Substitua por placeholders com especificações técnicas detalhadas
3. **Marcas e Logos**: Use apenas versões públicas ou crie placeholders com guidelines de recriação
4. **Funcionalidades**: Replique comportamentos, não implementações proprietárias específicas
5. **Documentação Legal**: Inclua aviso sobre direitos autorais e uso responsável
